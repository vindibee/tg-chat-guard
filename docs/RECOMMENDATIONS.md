# Рекомендованная конфигурация и план развития

Основано на разборе открытых решений (`umputun/tg-spam`, `Priler/samurai`,
`TiraelSedai/ClubDoorman`, `ramsayleung/bayes_spam_sniper`) и живой проверки
публичных блок-листов 11.09.2026. Полный отчёт:
<https://claude.ai/code/artifact/0c22076c-d956-4b39-bfe2-9a86e460b679>

## 1. Пороги на старте

Веса движка: ссылка 4.0, инвайт в приватный канал 5.0, скрытая ссылка 5.0,
призыв к действию 3.0, рефкод 4.0, упоминание 2.0, категория 4.0–4.5,
обфускация 2.0. Отсюда пороги:

```dotenv
# Первая неделя — только наблюдение
DRY_RUN=true
NOTIFY_CHAT=false          # уведомления в чат — шум, всё уходит в лог
LOG_JSON=true

REQUIRE_SPAM_FACTOR=true   # не трогать: это и есть защита от ложных срабатываний
DELETE_THRESHOLD=6.0       # ссылка + призыв = 7.0 → удаление
MUTE_THRESHOLD=9.0         # категория + инвайт = 9.5 → мьют
BAN_THRESHOLD=15.0         # было 13: автобан только для очевидного
MUTE_DURATION=3600

SAFE_DOMAINS=flibusta.is,flibusta.site,fantlab.ru,author.today,litres.ru,goodreads.com,libgen.is,wikipedia.org,habr.com,ozon.ru,labirint.ru
```

После недели в `DRY_RUN` разобрать таблицу `moderation_events`
(`action`, `score`, `reason`, `excerpt`) и снимать режим наблюдения.

В настройках самой группы включить **«Агрессивный антиспам»** (от 100 участников)
и slow mode 10–30 с — часть ботов Telegram отсечёт до нас.

## 3. План работ по убыванию пользы

| # | Что | Статус | Зачем |
|---|-----|--------|-------|
| 1 | Админ-чат модерации + кнопки отката | **готово** | Единственный способ увидеть свои ложные срабатывания |
| 2 | Область «одобренных» (старожил не проверяется) | **готово** | Главный анти-FP приём эталона |
| 3 | Внешняя репутация: LOLS + снимок CAS | **готово** | Ловит спамера по `user_id` до первого сообщения |
| 4 | Мета-проверки: кнопки, медиа-онли, story, `sender_chat`, дубликаты | план, ~120 строк | Спам без единого стоп-слова |
| 5 | `/spam`, `/ham`, жалобы участников | **готово** | Разметка для правки правил и регрессионные тесты |

ML-классификатор (`RUSpam/spam_deberta_v4`) и LLM-вето из плана исключены:
для личного бота это лишние 800 МБ памяти и внешняя зависимость, а правила
с требованием спам-фактора закрывают основной поток.

## 4. Блок-листы: как обращаться

Проверено запросами 11.09.2026:

* `https://api.lols.bot/account?id=<id>` → `{"ok":true,"user_id":1,"banned":true,"when":"..."}` — работает.
* `https://api.cas.chat/export.csv` — отдаёт список id построчно.
* `https://api.cas.chat/check?user_id=<id>` — вернул `Record not found` для **4 из 4** id,
  взятых из собственного экспорта CAS. Как единственный источник непригоден.

Реализованная схема: снимок CAS держим отсортированным `array("q")` прямо в
процессе — на живой выгрузке это **1 270 682 id и 9.7 МБ памяти** против ~70 МБ
у Redis-множества, поиск делением пополам. Обновление раз в 12 ч в фоне.
LOLS запрашивается онлайн (таймаут 2 с, суточный кэш в Redis) только на первом
сообщении автора и при входе в чат. Базы независимы — четыре свежих id из
экспорта CAS у LOLS числятся чистыми.

## 5. Чего не копировать

* **Капча новичкам** — для читательского чата это отток. Замена: первые сутки
  ссылка от новичка уходит на ревью в админ-чат.
* **`max-emoji=2`** — читатели ставят эмодзи пачками; порог от 8 или выключить.
* **Автобан по внешнему блок-листу** — только в связке «блок-лист + новичок + ссылка».
* **LLM на каждое сообщение** — дорого и само даёт ложные срабатывания; только вето
  поверх уже принятого решения.
* **Агрессивная чистка истории** — по кнопке админа, не автоматически.

## Оптимизация движка

Замеры на одном и том же тексте, медиана из 50 прогонов:

| Сообщение | Было | Стало | Выигрыш |
|---|---|---|---|
| типичное, 25 символов | 0.32 мс | **0.10 мс** | 3.2× |
| среднее, 300 символов | 3.42 мс | **0.62 мс** | 5.5× |
| предельное, 4000 символов | 37.8 мс | **8.5 мс** | 4.5× |

Что сделано:

1. **Альтернация вместо перебора.** 140 паттернов словаря собраны в 12 выражений
   (по одному на правило): один проход по тексту вместо пятнадцати. Число вызовов
   `re.search` на сообщение упало с 569 до 19.
2. **Быстрый предфильтр.** Одно выражение «есть ли вообще стоп-слово» отсекает
   чистые сообщения — а это почти весь трафик живого чата.
3. **Нормализация без посимвольных циклов.** Поиск диакритик и смешения алфавитов
   переведён на регулярки (C-скорость): 431 000 вызовов функций на 30 сообщений
   превратились в 4 000.
4. **Варианты строятся по необходимости.** Нет латиницы — не строим кириллический
   вариант, нет leet-символов — не строим leet-вариант.

## Предложения

### Ближайшее, дёшево и заметно

1. ~~**Проверять имя и username автора, а не только текст.**~~ **Сделано.**
   Имя и username проходят через тот же словарь; сработка — жёсткий фактор
   весом 3.5 (ссылка в имени — 4.0), но, как и стоп-слово в тексте, сама по себе
   не наказывает. Нейтральная финансовая лексика в имени игнорируется.
2. ~~**Детектор дубликатов.**~~ **Сделано.** Отпечаток склеенной формы текста,
   счёт разных авторов за час, вес растёт с числом аккаунтов (4.0 / 8.0 / 12.0)
   и не оправдывается книжным намерением. Повторы одного и того же автора и
   сообщения короче 40 символов не считаются.
3. ~~**Регрессионный прогон по собранной выборке.**~~ **Сделано.** Команда
   `/regress` в чате и `python -m bot.tools.regress` в консоли. Прогон идёт
   только по тексту (без блок-листов, дубликатов и профиля), поэтому
   воспроизводим; код возврата 1 при ложных срабатываниях — годится для CI.
4. ~~**Alembic.**~~ **Сделано.** Миграции накатываются при старте
   (`RUN_MIGRATIONS_ON_STARTUP`), существующая база принимается под управление
   без потери данных, неполная схема от старой версии — явная ошибка вместо
   молчаливой порчи. Тест `test_migrations_match_models` ловит расхождение
   моделей и ревизий.

### Среднее

5. **Мета-проверки** (пункт 4 исходного плана): инлайн-кнопки в сообщении,
   медиа без текста, ответ на историю, пересылка из канала.
6. **Пороги в БД вместо `.env`.** Команда `/set delete_threshold 7` без рестарта.
7. **Общий менеджер фоновых задач.** Сейчас самоудаление уведомлений и синхронизация
   CAS живут в разных множествах и не дожидаются остановки бота.
8. **Метрики.** Счётчики по категориям в Redis и команда `/stats` за неделю:
   видно, какие правила реально работают, а какие только шумят.

### Инфраструктура

9. **CI**: `ruff` + `pytest` + `mypy --strict` на каждый пуш. Сейчас проверки
   запускаются только вручную.
10. **Бенчмарк как тест.** Замер движка с порогом (например, не дольше 15 мс на
    4000 символов) — чтобы правка словаря не уронила производительность незаметно.
11. **Docker + systemd unit** для деплоя, health-check на `getMe`.
